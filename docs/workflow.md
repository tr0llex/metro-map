# Рабочие сценарии

Повседневные команды и порядок действий. README держит только вход, чтобы
витрина не превращалась в инструкцию.

## Полный список команд

```bash
npm run dev          # дев-сервер
npm run dev:pwa      # дев-сервер с включённым service worker
npm run dev:editor   # редактор схемы (editor.html)

npm run build        # tsc -b && vite build -> dist/
npm run preview      # предпросмотр прод-сборки

npm run lint
npm test             # Vitest (watch); в CI — npx vitest run
npm run e2e          # сквозные тесты по локальной прод-сборке
npm run check:css    # необъявленные CSS-переменные
npm run check:bundle # редактора нет в прод-бандле

npm run build:data     # пересобрать normalized/fullGraph.json (нужен Go)
npm run quality        # анализ качества схемы -> normalized/quality_report.json
npm run quality:check  # то же, но с ненулевым кодом выхода при регрессе
```

## Что покрывают сквозные тесты

`npm run e2e` сам собирает проект и поднимает `preview` — именно прод-сборку,
потому что service worker и precache в дев-режиме не существуют. Браузер
ставится один раз: `npx playwright install chromium`.

Покрыто: схема отрисовывается на канвасе (считаются непрозрачные пиксели —
пустой канвас в DOM выглядит так же, как полный) и перерисовывается при зуме;
пара станций даёт маршрут со временем, временем прибытия, пересадкой и перечнем
станций по отрезкам; альтернативные варианты переключаются; кнопка обмена меняет
станции местами и пересчитывает; service worker активируется, precache
наполняется, и повторный заход **без сети** поднимает приложение целиком со
схемой; тема переключается, переживает перезагрузку и тянет за собой
`meta theme-color`.

Сквозная проверка во всех тестах: любая ошибка в консоли браузера и любой
неудачный сетевой запрос валят тест.

Смоук по живому сайту запускается отдельно и руками, в CI на PR не висит:

```bash
npm run e2e:prod                          # https://metro.samoy.love
E2E_PROD_URL=https://... npm run e2e:prod # другой адрес
```

Стенд визуальной приёмки (`tools/visual-qa`) — про другое: он снимает скриншоты
настоящим Chromium в Docker и сравнивает картинки. Сквозные тесты проверяют
поведение, а не пиксели; см. [VISUAL_QA.md](VISUAL_QA.md).

## Поменялись данные метро или геометрия колец

`data/**` или `go-layout-solver/*.go`:

```bash
npm run build:data && npm run quality
```

Затем визуальная проверка: центр схемы, три кольца, 5–10 крупных узлов.

> **Важно:** UI не пересчитывает раскладку. Он использует готовые
> `layoutX/layoutY` из `normalized/fullGraph.json`. После любых правок решателя
> обязательно запускайте `npm run build:data`, затем `npm run quality`.

## Правки в редакторе

```bash
npm run dev:editor
```

Карандаш включает режим, внизу появляется панель сохранения. «Сохранить в
data/» (или Ctrl+S) записывает правки прямо в файлы и тут же пересобирает граф.
Панель показывает, что записано, и отдельно — что сохранить нельзя: такие правки
остаются только на экране, и об этом сказано прямо в ней.

Запись работает ТОЛЬКО в dev/editor-режиме: эндпоинт живёт в плагине
`scripts/editor/editorApiPlugin.ts` с `apply: 'serve'` и в сборку не попадает.

## Перед коммитом

```bash
npx tsc -b && npm run lint && npx vitest run && npm run build && npm run check:bundle
```

Тот же набор гоняет CI. Если менялась схема, туда же добавляется
`npm run quality` с коммитом обновлённого `normalized/quality_report.json` — CI
сверяет отчёт с этой базовой линией.
