## Блокер

### B-1. Одна повреждённая запись в localStorage полностью убивает приложение, и «восстановление» её не чинит

**Воспроизведение**
```js
localStorage.setItem('kitty-metro-recents-v1','[null]')
```
затем открыть приложение и либо (а) нажать чип «Недавние», либо (б) просто
построить любой маршрут — в том числе прийти по deep-link
`/?from=mos-1-1.103&to=mos-3-3.5`.

**Что происходит.** Белый экран ErrorBoundary «Что-то пошло не так»,
`Cannot read properties of null (reading 'fromStationId')` (проверено, текст взят
из блока «Подробности ошибки»). Кнопка «Очистить кэш и перезагрузить» чистит
Cache Storage и снимает SW, но **намеренно не трогает localStorage**
(`src/components/ErrorBoundary.tsx:13-33`, текст на `:126-128` прямо обещает, что
«маршруты и избранное сохранятся»). После перезагрузки битая запись на месте, и
приложение падает снова — вечный цикл. Выйти можно только очисткой данных сайта
руками, чего обычный пользователь не сделает.

**Причина.** При чтении хранилища проверяется только `Array.isArray`, форма
элементов не валидируется: `src/App.tsx:474-521`. Дальше элементы разыменовываются
без защиты — в обработчике ответа воркера `src/App.tsx:1306-1309`
(`prev.filter(item => !(item.fromStationId === ...))`, падение внутри state-updater),
и при рендере чипов `src/App.tsx:3109-3118` и `:3136-3145`.

**Что должно.** Записи должны валидироваться по форме при чтении (все поля —
строки/число), невалидные — молча отбрасываться, а хранилище перезаписываться
очищенным списком. Экран ошибки должен уметь сбросить и localStorage (хотя бы
отдельной кнопкой «Сбросить все данные»), иначе он не является восстановлением.

**Severity:** блокер. **Уверенность:** воспроизвёл (оба сценария).

## Серьёзные

### S-1. После pinch-zoom последний поднятый палец засчитывается как тап по станции

**Воспроизведение** (мобильный вьюпорт, воспроизведено синтетическими
`TouchEvent` на `canvas.metro-map-svg`):
1. палец 1 вниз, палец 2 вниз (pinch), несколько `touchmove` двумя пальцами;
2. поднять палец 1 (`touchend`, `touches=[палец2]`);
3. поднять палец 2 над любой станцией.

Результат: поле «Откуда» заполнилось «Арбатская», хотя пользователь только
масштабировал карту. На карте с уже заданным «Откуда» тем же жестом молча
подменяется «Куда» и **перестраивается маршрут**.

**Причина.** `src/components/MetroMap.tsx:4611-4668`. Флаг `hadPinch` считывается
из `pinchStartDistanceRef`, и он же обнуляется на **первом** `touchend`
(`:4625-4628`). На втором `touchend` (последний палец) `hadPinch === false`,
`hasDragged` за время pinch никто не выставлял (ветка pinch в `handleTouchMove`
`:4551-4608` не трогает `hasDragged`), поэтому проходит проверка
`:4654` и вызывается `handleStationClick`.

**Что должно.** Жест должен помечаться «многопальцевым» до полного отрыва всех
касаний (например, флаг `multiTouchSessionRef`, сбрасываемый только когда
`event.touches.length === 0` и прошёл `touchend` без остатка), либо pinch должен
выставлять `hasDragged = true`.

**Severity:** серьёзный (pinch — базовый жест схемы метро, а последствие —
незаметная подмена точки маршрута). **Уверенность:** воспроизвёл.

### S-2. Чистильщик легаси-SW стирает precache нового service worker — офлайн ломается ровно у обновляющихся пользователей

**Условия.** У пользователя стоит установленная PWA со старой регистрацией
`/sw.js` (файл до сих пор раздаётся продом, проверено: `GET /sw.js` → 200).

**Что происходит.** `src/App.tsx:924-972` при обнаружении легаси-регистрации
делает `caches.keys()` → `caches.delete(k)` **для всех кэшей origin'а**
(`:956-957`), и только потом снимает старую регистрацию. К этому моменту новый
`kitty-metro-sw.js` уже установлен и уложил precache — его и удаляют. Workbox
повторно `install` не выполняет, поэтому precache остаётся пустым до следующего
деплоя SW. Приложение продолжает работать онлайн (у `PrecacheStrategy` есть
`fallbackToNetwork`), но **офлайн-режим — заявленная главная фича — молча
перестаёт работать**.

Тот же паттерн в `public/sw.js:15-38` (легаси-воркер сам чистит все кэши в
`activate`) — при неудачном порядке событий он делает ровно то же самое.

**Что должно.** Удалять только кэши, принадлежащие старой версии (по префиксу
имени), либо после чистки принудительно переустанавливать новый SW
(`registration.update()` + ожидание нового `install`), либо не трогать кэши
вообще — старые всё равно уберёт `cleanupOutdatedCaches`.

**Severity:** серьёзный. **Уверенность:** выведено из кода (сценарий требует
реальной старой установки, стенда с ней нет).

### S-3. Ввод точного названия станции и Enter выбирают ДРУГУЮ станцию

**Воспроизведение.** В поле «Откуда» ввести ровно `Аэропорт`, нажать Enter.
В поле оказывается **«Аэропорт Внуково»** (проверено в браузере).

**Причина.** Подсказки строятся простым `includes` без ранжирования и обрезаются
по первым шести совпадениям в порядке данных (`src/App.tsx:1601-1622` и
`:1624-1645`), а Enter при `fromSuggestionIndex === -1` берёт `suggestions[0]`
(`src/App.tsx:2531-2544`, для «Куда» — `:2593-2606`).

По текущим данным точное совпадение оказывается НЕ первым для четырёх станций:
`Аэропорт → Аэропорт Внуково`, `Сокол → Сокольники`,
`Лихоборы → Верхние Лихоборы`, `Косино → Новокосино`.
«Аэропорт» и «Аэропорт Внуково» находятся на противоположных концах города —
пользователь получает совершенно другой маршрут и не обязательно это заметит.

**Что должно.** Ранжирование подсказок: точное совпадение → префикс → подстрока;
при точном совпадении Enter обязан выбирать именно его.

**Severity:** серьёзный. **Уверенность:** воспроизвёл.

### S-4. В продакшене не доходят заголовки безопасности

**Воспроизведение**
```
curl -sSI https://metro.samoy.love/            # нет X-Frame-Options / X-Content-Type-Options
curl -sSI https://metro.samoy.love/assets/kitty-metro-index-*.js   # заголовки есть
```

**Что происходит.** `X-Content-Type-Options`, `X-Frame-Options`,
`X-XSS-Protection` объявлены на уровне `server` (`deploy/nginx/metro.conf:39-41`),
но каждый `location` объявляет собственные `add_header`
(`:50-55`, `:63-67`, `:70-74`, `:77-81`, …). В nginx `add_header` не
наследуется, если на текущем уровне есть хоть один свой `add_header`, — поэтому
на `index.html`, service worker, манифесте и всех нехешированных файлах
заголовков нет. Они уцелели только в `location ^~ /assets/`, где своих
`add_header` нет.

**Что должно.** Вынести заголовки безопасности в `include`-сниппет и повторить в
каждом `location`, либо перейти на `map`/`more_set_headers`.

**Severity:** серьёзный (защита от кликджекинга главной страницы отсутствует).
**Уверенность:** воспроизвёл на проде.

## Средние

### M-1. `/assets/**` отдаётся без `Cache-Control` — хешированные бандлы не кэшируются

**Воспроизведение.** `curl -sSI https://metro.samoy.love/assets/kitty-metro-index-J0BsHu_y.js` —
в ответе нет ни одного `Cache-Control`.

**Причина.** `deploy/nginx/metro.conf:58-61` — блок `location ^~ /assets/`.
Модификатор `^~` запрещает проверку regex-локаций, поэтому правило
`public, max-age=31536000, immutable` для файлов с хешем (`:84-88`) до `/assets/`
никогда не доходит, а своего заголовка у блока нет.

**Что должно.** Immutable-кэш на год для хешированных ассетов; сейчас браузер
ревалидирует каждый чанк на каждой навигации.

**Severity:** средний. **Уверенность:** воспроизвёл на проде.

### M-2. Битый или самопротиворечивый deep link молча не делает ничего

**Воспроизведение.** Открыть `/?from=mos-1-1.103&to=mos-1-1.103` (или с
несуществующим id). Проверено: поля пустые, сообщения нет, URL остаётся с
параметрами — выглядит как «ссылка не работает».

**Причина.** `src/App.tsx:1536-1560`: при `!fromStationResolved`, `!toStationResolved`
или `params.fromId === params.toId` эффект просто `return` без единого следа.

**Что должно.** Показать понятную ошибку («Ссылка на маршрут повреждена» /
«Станции совпадают») и очистить query-параметры, чтобы перезагрузка не повторяла
пустой сценарий.

**Severity:** средний. **Уверенность:** воспроизвёл.

### M-3. В продакшене воркер каждый раз пересобирает граф заново — предрасчёт `setRoutingGraph` не используется

**Условия.** Любой запрос маршрута в проде.

**Что происходит.** `App` всегда передаёт `edgeOverrides` (`src/App.tsx:1500`), а в
проде это `EMPTY_RECORD = {}` из
`src/editor/noopEditorController.ts:28,57`. В воркере
`src/metro/routing.ts:96` делает `hasOverrides = !!options?.edgeOverrides`, и
пустой объект — истина. Значит `useBaseGraph === false`
(`:98`), и на **каждый** запрос заново строятся `appliedEdges` (368 рёбер с
дедупликацией), `allStationIds` (Set на 306 станций),
`buildAdjacencyListFromFullGraph` и `buildEdgeByKey` (`:111-162`) — ровно та
работа, которую `setRoutingGraph` (`:32-39`) уже сделал один раз на старте.

Побочный эффект: путь с оверрайдами дедуплицирует рёбра по неориентированному
ключу, то есть параллельные рёбра между одной парой станций были бы отброшены
(в текущих данных таких нет — проверено, 368 рёбер = 368 уникальных пар).

**Что должно.** Проверять `Object.keys(edgeOverrides).length > 0` (или не слать
пустые оверрайды из прод-заглушки вовсе).

**Severity:** средний (мёртвая оптимизация + расхождение поведения прод/редактор).
**Уверенность:** выведено из кода.

### M-4. Редактор: redo пропадает после каждого undo

**Условия.** Режим редактора (dev/editor-сборка), любая правка, меняющая
координаты, затем Ctrl+Z.

**Что происходит.** `applyEditorSnapshot` (`src/editor/useEditorController.ts:175-190`)
поднимает `editorLayoutApplyToken`, MetroMap применяет координаты и вызывает
`onCanonicalLayoutChange` (`src/components/MetroMap.tsx:2169-2202`) — тот срабатывает,
потому что JSON снапшота действительно изменился. `handleCanonicalLayoutChange`
(`useEditorController.ts:192-196`) кладёт **новые объекты** в
`canonicalGrid/RingShapes/StationParams`. Они входят в `makeEditorSnapshot`
(`:124-152`), значит меняется `pushEditorHistory`, значит перезапускается эффект
`:290-304`, а `areEditorSnapshotsShallowEqual` (`:29-47`) сравнивает по ссылкам и
даёт `false`. `pushEditorHistory` (`:154-173`) делает
`items.slice(0, prev.index + 1)` — вся ветка redo отрезается.

**Что должно.** Либо не класть в снапшот истории производные canonical-данные,
либо сравнивать их по значению, либо помечать применение снапшота флагом
«история сейчас не пишется».

**Severity:** средний. **Уверенность:** выведено из кода.

### M-5. Редактор: `applyEditorSnapshot` вызывается внутри state-updater

`src/editor/useEditorController.ts:198-216` — `handleEditorUndo`/`handleEditorRedo`
делают побочные эффекты (десяток `setState`) прямо внутри функции-апдейтера
`setEditorHistory`. React считает апдейтер чистым и в StrictMode вызывает его
дважды, то есть undo применяет снапшот дважды и дважды увеличивает
`editorLayoutApplyToken`.

**Что должно.** Читать нужный индекс отдельно (через ref или `useReducer` с
эффектом), апдейтер оставить чистым.

**Severity:** средний. **Уверенность:** выведено из кода.

### M-6. Провал загрузки графа в воркере — навсегда, «Попробовать ещё раз» бесполезна

**Условия.** Первый запуск без сети/до наполнения precache, 5xx, битый JSON.

**Что происходит.** `src/routeWorker.ts:39-46` создаёт `graphReady` **один раз** на
время жизни воркера. Отклонённый промис остаётся отклонённым, и `:70-85` на любой
последующий запрос отвечает `routeError` с тем же текстом. В `App` кнопка
«Попробовать ещё раз» (`src/App.tsx:1525-1532`) переигрывает запрос в тот же
воркер — результат не меняется. Воркер пересоздаётся только при перезагрузке
страницы (`src/App.tsx:1335-1353`).

Дополнительно: nginx отдаёт `/kitty-metro-routing-graph.json` через
`location /` с `try_files $uri /index.html` (`deploy/nginx/metro.conf:50-55`) —
если файл когда-нибудь пропадёт, воркер получит HTML со статусом 200,
`response.ok` будет true, и ошибка вылезет как невнятный «Unexpected token '<'».

**Что должно.** Повторная попытка загрузки графа при следующем запросе (или
пересоздание воркера в `handleRetryRoute`), плюс проверка `content-type`.

**Severity:** средний. **Уверенность:** выведено из кода.

### M-7. 9-секундный таймаут запроса включает в себя загрузку графа

`ROUTE_REQUEST_TIMEOUT_MS = 9000` (`src/App.tsx:63`) заводится в момент
`postMessage` (`:1506-1516`), а воркер отвечает только после `graphReady`. На
медленной сети (первый запуск, 2G, холодный старт PWA) первый маршрут показывает
«Расчёт маршрута занял слишком много времени», хотя воркер ответит через
секунду — но его ответ уже выброшен из `pending` (`:1511-1512`).

**Что должно.** Считать таймаут от момента готовности графа, либо разделить
сообщения «граф ещё грузится» и «расчёт завис».

**Severity:** средний. **Уверенность:** выведено из кода.

### M-8. Одинаковые названия станций в подсказках неразличимы

В данных 43 названия встречаются больше одного раза (Арбатская, Смоленская,
Комсомольская, Деловой центр ×3 и т. д.). Подсказка рисует только точку цвета
линии (`src/components/RouteForm.tsx:288-293`), название линии не показывается,
а чипы избранного/недавнего печатают «Арбатская → Арбатская». Пользователь не
может осознанно выбрать нужную из двух одинаковых строк.

**Что должно.** Показывать название линии (или хотя бы номер) второй строкой,
когда название неуникально.

**Severity:** средний. **Уверенность:** выведено из кода + проверено по данным.

### M-9. `setMapVisibleInsets` никогда не «схлопывается» — лишние рендеры на каждый resize/scroll

`src/App.tsx:1072-1077` всегда возвращает **новый объект**, даже когда все четыре
числа не изменились. React сравнивает по `Object.is`, поэтому каждое из 16 кадров
«всплеска» (`:1081-1099`) и каждое событие `resize`/`visualViewport scroll`
вызывает перерендер `App` → перерендер `MetroMap` (мемоизация по пропу
`visibleInsets` не срабатывает) → перезапуск эффекта автофита
(`src/components/MetroMap.tsx:2283-2434`, зависимость `visibleInsets`), который
каждый раз заводит новый rAF-цикл длиной до 520 мс.

**Что должно.** Возвращать `prev`, если значения совпали.

**Severity:** средний (перф на слабых телефонах, при открытии клавиатуры и скрытии
адресной строки). **Уверенность:** выведено из кода.

### M-10. Легаси `public/sw.js` делает network-only без фолбэка

`public/sw.js:40-42`: `event.respondWith(fetch(event.request))` без `catch`.
Пока этот воркер контролирует клиента (а он раздаётся и будет раздаваться
до 2027-02-01 по комментарию в файле), **любой офлайн-запрос падает с сетевой
ошибкой**, включая навигацию: пользователь старой установки без сети получает
не приложение, а страницу ошибки браузера.

**Что должно.** Либо не регистрировать `fetch` вообще (тогда запросы идут мимо
SW), либо `fetch(...).catch(() => caches.match(request))`.

**Severity:** средний. **Уверенность:** выведено из кода.

### M-11. `touchcancel` обрабатывается как обычный `touchend` — отменённый жест может выбрать станцию

`src/components/MetroMap.tsx:4760` вешает `onTouchCancel={handleTouchEnd}`.
`handleTouchEnd` (`:4654`) не отличает отмену от отпускания и при
`changedTouches.length === 1` выполняет hit-test и `handleStationClick`.
`touchcancel` прилетает, когда жест перехватила система (шторка уведомлений,
жест «назад» от края, входящий звонок) — пользователь получает выбор станции от
жеста, который он не завершал.

**Что должно.** Отдельный обработчик отмены: сбросить состояние жеста и ничего
не выбирать.

**Severity:** средний. **Уверенность:** выведено из кода (механизм тот же, что у
воспроизведённого S-1).

### M-12. После pinch оставшийся палец перестаёт панорамировать

`handleTouchEnd` (`src/components/MetroMap.tsx:4611-4623`) на первом отпускании
сбрасывает `isPanning`/`lastPointRef`, не смотря на то, что на экране остался
второй палец. Поэтому `handleTouchMove` (`:4514`) — ветка одного пальца —
не срабатывает: карта «залипает», пока палец не оторвут и не поставят заново.

**Что должно.** При `event.touches.length === 1` после pinch перезапускать pan с

## Найдено, но воспроизвести не удалось

### N-1. Недетерминированность холодного старта Go-солвера

`optimizeDistances` (`go-layout-solver/layout_bootstrap.go:912-971`) строит список
идентификаторов обходом map (`:917-919`) — в Go порядок итерации map случаен от
запуска к запуску, — а алгоритм порядко-зависим: `st1` сдвигается на месте, и
последующие станции читают уже сдвинутые координаты.

**Проверка.** Три прогона
`go run . -csv ... -connections ... -yandex ... -travel_times ...` (без
`-editor_overrides`) дали **побайтово одинаковый** `fullGraph.json`
(md5 `890ca9cd…` во всех трёх). Причина, судя по всему, в известной поломке
масштаба холодного старта: bbox выходит 24830×20117 px, минимальное попарное
расстояние 14.88 px при `minDist = 16`, то есть взаимодействующих пар единицы и
они не пересекаются — порядок не влияет. После починки масштаба схема сожмётся,
пар станет много, и недетерминированность проявится.

**Severity:** мелочь сейчас, средний после починки масштаба.
**Уверенность:** подозрение (механизм в коде виден, эффекта на текущих данных нет).

### N-2. Дедупликация рёбер по неориентированному ключу может отбросить параллельные рёбра

`src/metro/routing.ts:120-144` (путь с оверрайдами/manual-рёбрами) оставляет
только первое ребро на пару станций. Если когда-нибудь в графе появятся два
ребра между одной парой (например, перегон и пересадка между теми же двумя id),
одно из них исчезнет из расчёта, причём только в режиме с оверрайдами — то есть
редактор и прод посчитают маршрут по-разному.

**Проверка.** В текущем `normalized/fullGraph.json` 368 рёбер и 368 уникальных
неориентированных пар — дублей нет, воспроизвести нечем.

**Severity:** мелочь (латентно). **Уверенность:** выведено из кода.
