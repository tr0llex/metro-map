# Визуальная приёмка (Docker + настоящий Chromium)

## Зачем это нужно

Встроенная браузерная панель в среде разработки не отдаёт кадры (`document.hidden === true`,
`requestAnimationFrame` не вызывается), поэтому приложение проверялось только замерами DOM
и офлайн-отрисовкой. Этот стенд поднимает **настоящий Chromium** в контейнере и снимает
реальные скриншоты собранного приложения.

## Как воспроизвести одной командой

Windows / Docker Desktop:

```powershell
pwsh -File tools/visual-qa/run.ps1
```

Linux / macOS / Git Bash:

```bash
bash tools/visual-qa/run.sh
```

Скрипт делает три вещи:

1. `npm run build` — собирает приложение в `dist/`;
2. `docker build -t metromap-visual-qa tools/visual-qa` — образ на базе
   `mcr.microsoft.com/playwright:v1.49.0-jammy` (Chromium уже внутри; первая сборка тянет ~2 ГБ);
3. `docker run` с двумя монтированиями: `dist/ → /app/dist` (только чтение) и
   `docs/visual-qa/ → /out`.

Внутри контейнера `shoot.mjs` поднимает собственный статик-сервер на `127.0.0.1:4173`
над `/app/dist` и ходит в него локально. **До хоста контейнер не ходит вообще**
(`host.docker.internal` не нужен) — это снимает класс проблем с сетью Docker Desktop
на Windows и делает прогон одинаковым на любой машине.

Флаги:

| Флаг (ps1) | Переменная (sh) | Смысл |
|---|---|---|
| `-SkipBuild` | `SKIP_BUILD=1` | не пересобирать `dist` |
| `-Only mobile` | `QA_ONLY=mobile` | снять только один профиль (`mobile` / `desktop`) |
| `-Out <path>` | `OUT_DIR=<path>` | другой каталог для скриншотов |

Дополнительные диагностические прогоны (запускаются поверх того же образа):

```bash
docker run --rm -v "$PWD/dist:/app/dist:ro" -v "$PWD/docs/visual-qa:/out" \
  -v "$PWD/tools/visual-qa/probe.mjs:/qa/probe.mjs:ro" metromap-visual-qa node probe.mjs
```

* `probe.mjs` — скроллятся ли детали маршрута, как рисуется «дальний переход», крупный план узла;
* `probe-touch.mjs` — реальный тач-свайп (CDP `Input.dispatchTouchEvent`) внутри шторки;
* `probe-zoomout.mjs` — видно ли схему целиком при минимальном зуме.

## Результаты

### Ошибки консоли и сети

**Чисто.** За 6 полных сессий (2 профиля × 3 сценария) в основном прогоне:

* JS-ошибок (`pageerror`, в том числе необработанных промисов) — **0**;
* сообщений `console.error` / `console.warn` — **0**;
* HTTP-ответов ≥ 400 и упавших запросов — **0** (включая service worker, манифест и иконки).

Маршруты считаются воркером мгновенно, скелетон загрузки не успевает появиться.

### Читаемость схемы — **проблемно в центре**

За пределами Садового кольца схема читается хорошо: подписи не сталкиваются, привязка
подписи к станции однозначна (`desktop-20-zoomed-out.png`, `mobile-20-zoomed-out.png`).

В плотном центре — плохо (`desktop-17-hub-biblioteka.png`, `desktop-05-map-zoom-center.png`):

* **«Боровицкая»** перечёркнута насквозь тремя линиями (Арбатско-Покровская, Филёвская,
  Серпуховско-Тимирязевская) и вдобавок налезает на «Библиотека им.Ленина» — практически нечитаема;
* **«Библиотека им.Ленина»** — вторая строка перечёркнута тёмно-синей линией;
* **«Александровский сад»** перечёркнута серой и красной линиями, налезает на «Арбатская»;
* **«Театральная»** перечёркнута синей линией и наезжает на кружок станции,
  «Площадь Революции» стоит вплотную под ней;
* **«Охотный ряд»** висит в пустоте — какой кружок ему принадлежит, непонятно;
* две подписи **«Арбатская»** (Филёвская и Арбатско-Покровская) стоят по разные стороны узла,
  пользователю не ясно, что это разные станции одного пересадочного узла;
* **«ЗИЛ»**, **«Волгоградский проспект»** перекрыты кружками станций/линиями (`desktop-04`).

Это согласуется с `normalized/quality_report.json`: `labels.crossedByLines` = 5.73 % (WARN),
`labels.detached` = 9.54 % при цели 3 % (WARN).

### Пересадочные узлы — **половина отлично, один узел провален**

Отлично читаются как единый узел: **Кузнецкий мост**, **Китай-город**, **Третьяковская**,
**Парк культуры**, **Тверская**, **Театральная / Охотный ряд / Площадь Революции** —
кружки в общей капсуле, «пирог» из цветов линий читается сразу (`mobile-06`, `desktop-17`).

Провален узел **Библиотека им.Ленина / Боровицкая / Арбатская / Александровский сад**:
четыре кружка разбросаны по четырём разным точкам вдоль своих линий, объединяющей капсулы нет
вообще. Визуально это четыре независимые станции, а не крупнейший пересадочный узел Москвы
(`desktop-17-hub-biblioteka.png`).

Разъехавшихся или слипшихся кружков внутри капсул не обнаружено.

### Кольца — **хорошо**

Кольцевая (коричневая), БКЛ (розовая) и МЦК (голубая) нарисованы гладкими замкнутыми кривыми,
станции лежат **ровно на кривой**, «съезда» нет ни на одном масштабе
(`desktop-20-zoomed-out.png`, `desktop-04-map-full.png`, `desktop-17`).
Заметно только неравномерное угловое распределение станций по МЦК и БКЛ — местами станции
сбиваются в кучки, местами большие пустые дуги (совпадает с `rings.spacingUnevenness` = 67 %, WARN).
Это заметно, но не мешает.

### Маршрут — **отлично**

* Маршрут рисуется поверх остальных линий, вся остальная схема гасится до бледного —
  видно сразу и однозначно (`mobile-08-route-built.png`, `desktop-10-route-details.png`);
* конечные точки помечены крупными пинами **A** и **B** — понятно (`desktop-16`);
* **дальний переход** (out-of-station) рисуется отдельной ярко-малиновой пунктирной перемычкой
  между двумя кружками и подписан в панели «Дальний переход • ~7 мин» — отличается от обычной
  пересадки однозначно (`desktop-16-long-transfer-zoom.png`);
* после построения карта сама подгоняет масштаб под маршрут;
* детали: карточки «Поезд: A → B», список станций, карточка «Пересадка: … • Переход • ~4 мин»,
  время прибытия, кнопки «поделиться» и «в избранное» — всё на месте и корректно.

Замечание: при подгонке под длинный маршрут масштаб падает так, что подписи станций на карте
становятся ~5 px и нечитаемы (`desktop-10`). Маршрут виден, названия — нет.

### Вёрстка UI — **чисто на десктопе, одно замечание на мобильном**

* desktop 1440×900: **ни один элемент не выходит за вьюпорт** (проверка обходом всех
  видимых элементов — 0 нарушений); боковая панель вместо шторки работает как задумано;
* mobile 390×844: за вьюпорт выходит только горизонтальный скроллер вариантов маршрута
  (это его нормальное поведение) и содержимое шторки, которое скроллится — **проверено
  настоящим тач-свайпом**: `scrollTop` доходит до 830 px, последний шаг маршрута полностью
  виден (`mobile-19-touch-after-swipe.png`). Обрезания контента нет;
* длинные названия («Бульвар Адмирала Ушакова», «Пересадка: Бульвар Дмитрия Донского →
  Улица Старокачаловская») переносятся и карточки не ломают;
* поля «Откуда»/«Куда» доступны, подсказки открываются вверх над полем и не перекрываются
  клавиатурой (`mobile-07-suggestions.png`).

### Общее впечатление

Продукт выглядит цельным и приятным: заставка, розовая тема, шапка с маршрутом, пилюли линий,
детали маршрута — всё аккуратно и «по-продуктовому». Слабое место ровно одно и оно
концентрированное — **типографика и узлы в пределах Садового кольца**. Именно туда пользователь
смотрит первым делом, потому что стартовый вид открывается прямо в центре.

## Найденные дефекты

### P1 — чинить до релиза

**VQA-1. Узел «Библиотека им.Ленина / Боровицкая / Арбатская / Александровский сад» не
читается как пересадочный узел.** Четыре станции разнесены на десятки пикселей, общей капсулы
нет. Пользователь не поймёт, что между ними есть переход.
Скриншот: `desktop-17-hub-biblioteka.png`, `desktop-05-map-zoom-center.png`.

**VQA-2. Подписи в центре перечёркнуты линиями и налезают друг на друга.**
Худшие случаи: «Боровицкая» (три линии насквозь + наложение), «Библиотека им.Ленина»,
«Александровский сад», «Театральная». Читаемость в самой важной части схемы ниже приемлемой.
Скриншот: `desktop-17-hub-biblioteka.png`, `mobile-04-map-full.png`.

### P2 — желательно до релиза

**VQA-3. Стартовый вид не показывает схему целиком.** На мобильном после заставки видно
примерно 1/8 схемы — плотный центр с обрезанными по краям подписями («елорусская», «ковская»,
«рбатская»). На десктопе обрезаны МЦК и все окраины. Чтобы увидеть схему, нужно 8 раз нажать «−».
Первое впечатление — «приложение сломалось и показывает кусок».
Скриншоты: `mobile-04-map-full.png`, `desktop-04-map-full.png`, `mobile-20-zoomed-out.png`.

**VQA-4. Модальная карточка «Поставь метро как приложение» полупрозрачна.** Сквозь тело
карточки читаются подписи станций («Библиотека им.Ленина», «Третьяковская», «Новокузнецкая»),
текст инструкции на этом фоне читается плохо. Подложка карты при этом почти не затемнена.
Скриншоты: `mobile-02-install-guide.png`, `desktop-02-install-guide.png`.

**VQA-5. Панель ввода на десктопе тоже просвечивает.** Сквозь неё чётко видны «Деловой центр»,
«Улица 1905 года», «Москва-Сити». Выглядит как недоприменённый `backdrop-filter`, а не как
задуманное стекло. Скриншот: `desktop-04-map-full.png`.

**VQA-6. Даже на минимальном зуме схема не помещается на мобильном по ширине** — левый и
правый края (Саларьево, Новокосино, Печатники) остаются за экраном, нужен пан.
Скриншот: `mobile-20-zoomed-out.png`.

### P3 — косметика / на потом

**VQA-7.** При подгонке карты под длинный маршрут подписи станций уменьшаются до нечитаемых
~5 px (`desktop-10-route-details.png`).

**VQA-8.** При прокрутке деталей маршрута контент обрезается по верхней кромке шторки/панели
без затухания, а поля «Откуда/Куда» и ручка шторки уезжают вместе с контентом — чтобы поменять
станции, надо сначала прокрутить обратно (`mobile-19-touch-after-swipe.png`, `desktop-14`).

**VQA-9.** Пины **A**/**B** крупные и перекрывают соседние подписи («Стрешнево»)
(`desktop-16-long-transfer-zoom.png`).

**VQA-10.** На заставке блюр фона не доходит до верхней и нижней кромок экрана — по краям
видны резкие подписи станций (`mobile-01-splash.png`).

**VQA-11.** В карточке установки на мобильном иконка Hello Kitty визуально «врезается»
в двухстрочный заголовок (`mobile-02-install-guide.png`).

**VQA-12.** На заставке публикуется личный e-mail автора (`BY ALEX@SAMOY.LOVE`). Не баг,
но перед публичным релизом стоит осознанно подтвердить.

## Вердикт

**Условно готово к релизу.**

Функционально приложение здорово: ноль ошибок в консоли и сети, маршруты строятся, альтернативы,
детали, пересадки и дальние переходы отображаются корректно, вёрстка не ломается ни на 390×844,
ни на 1440×900, длинные названия переносятся, тач-жесты работают.

Блокеров, ломающих сценарий «построить маршрут», не найдено. Но два дефекта (VQA-1, VQA-2)
бьют по главному обещанию продукта — «красивая читаемая схема метро» — и находятся ровно там,
куда приложение открывается по умолчанию. Плюс VQA-3 портит первое впечатление за первые
две секунды.

Рекомендация: **чинить VQA-1, VQA-2, VQA-3 перед публичным релизом**; VQA-4…VQA-6 —
следующим патчем; P3 — по возможности.
