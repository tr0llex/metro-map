# Визуальная приёмка (Docker + настоящий Chromium)

Это **инструкция по запуску**. Она живёт долго.
Результаты конкретного прогона — отдельный датированный документ:
[`VISUAL_QA_REPORT.md`](VISUAL_QA_REPORT.md). Раньше это был один файл, и понять,
какая его половина ещё верна, было невозможно.

## Зачем это нужно

Встроенная браузерная панель в среде разработки не отдаёт кадры (`document.hidden === true`,
`requestAnimationFrame` не вызывается), поэтому приложение проверялось только замерами DOM
и офлайн-отрисовкой. Этот стенд поднимает **настоящий Chromium** в контейнере и снимает
реальные скриншоты собранного приложения.

## Как воспроизвести одной командой

Windows / Docker Desktop:

```powershell
pwsh -File tools/visual-qa/run.ps1
```

Linux / macOS / Git Bash:

```bash
bash tools/visual-qa/run.sh
```

Скрипт делает:

1. `npm run build` — собирает приложение в `dist/`;
2. `docker build -t metromap-visual-qa tools/visual-qa` — образ на базе
   `mcr.microsoft.com/playwright:v1.49.0-jammy` (Chromium уже внутри; первая сборка тянет ~2 ГБ);
3. четыре прогона в этом образе с монтированиями `dist/ → /app/dist` (только чтение)
   и каталога результатов `→ /out`: `shoot.mjs` (сценарии 01–12), затем пробники
   `probe.mjs` (13–17), `probe-touch.mjs` (18–19), `probe-zoomout.mjs` (20).

Внутри контейнера поднимается собственный статик-сервер на `127.0.0.1:4173`
над `/app/dist`. **До хоста контейнер не ходит вообще** (`host.docker.internal` не нужен) —
это снимает класс проблем с сетью Docker Desktop на Windows и делает прогон одинаковым
на любой машине.

### Куда попадают скриншоты

По умолчанию — в **`.visual-qa/` в корне репозитория**, а он в `.gitignore`.
Прогон — это диагностика, а не документ: раньше умолчанием был `docs/visual-qa`,
и штатная команда оставляла два десятка изменённых PNG в рабочем дереве.

Зафиксировать новый набор в документации нужно **осознанно**:

```bash
QA_PUBLISH=1 bash tools/visual-qa/run.sh     # или: pwsh -File tools/visual-qa/run.ps1 -Publish
```

После этого проверьте `git status` и коммитьте вместе с обновлением
[`VISUAL_QA_REPORT.md`](VISUAL_QA_REPORT.md) — иначе картинки и выводы разойдутся.

### Флаги

| Флаг (ps1) | Переменная (sh) | Смысл |
|---|---|---|
| `-SkipBuild` | `SKIP_BUILD=1` | не пересобирать `dist` |
| `-Only mobile` | `QA_ONLY=mobile` | снять только один профиль (`mobile` / `desktop`) |
| `-NoProbes` | `QA_PROBES=0` | пропустить пробники (снять только 01–12) |
| `-Publish` | `QA_PUBLISH=1` | скопировать результат в `docs/visual-qa/` |
| `-Out <path>` | `OUT_DIR=<path>` | другой каталог для скриншотов |

## Профили и сценарии

Профили: **mobile** 390×844, `deviceScaleFactor: 2`, тач, UA iPhone; **desktop** 1440×900,
мышь (≥1024px → боковая панель вместо шторки).

| Файл | Чем снимается | Что на нём |
|---|---|---|
| `01-splash` | `shoot.mjs` | заставка (первые ~450 мс) |
| `02-install-guide` | `shoot.mjs` | карточка «поставь как приложение» на чистом `localStorage` |
| `03-onboarding-hint` | `shoot.mjs` | подсказка онбординга после закрытия карточки |
| `04-map-full` | `shoot.mjs` | стартовый экран после заставки |
| `05/06-map-zoom-center` | `shoot.mjs` | зум в плотный центр, два уровня приближения |
| `07-suggestions` | `shoot.mjs` | подсказки станций в поле «Откуда» |
| `08-route-built` | `shoot.mjs` | построенный маршрут Планерная → Бунинская аллея |
| `09-route-alternatives` | `shoot.mjs` | варианты маршрута с цветными пилюлями линий |
| `10-route-details`, `12-route-details-bottom` | `shoot.mjs` | раскрытая шторка/панель с деталями |
| `11-route-zoom` | `shoot.mjs` | маршрут крупно |
| `13-details-scrolled`, `14-details-wheel` | `probe.mjs` | прокрутка деталей маршрута |
| `15/16-long-transfer` | `probe.mjs` | «дальний переход» Октябрьское поле → Панфиловская |
| `desktop-17-hub-biblioteka` | `probe.mjs` | крупный план узла Библиотека им.Ленина / Боровицкая / Арбатская |
| `mobile-18/19-touch-*` | `probe-touch.mjs` | тач-свайп по шторке (CDP `Input.dispatchTouchEvent`) |
| `20-zoomed-out` | `probe-zoomout.mjs` | схема на минимальном зуме |

Диагностика прогона — `report.json`, `probe.json`, `probe-touch.json` в том же каталоге.

**Полный прогон снимает весь набор 01–20.** Так было не всегда: пробники раньше не
входили в `run.sh` и запускались вручную длинной `docker run`-командой из документации,
поэтому 11 скриншотов в `docs/visual-qa/` не обновлялись месяцами, а выводы отчёта
опирались именно на них.

## Как читать результат

1. `report.json` — ошибки консоли, `pageerror`, ответы ≥400. Здесь любое ненулевое
   значение это дефект, спорить не о чем.
2. Скриншоты — читаемость схемы, вёрстка, узлы, кольца, маршрут.
3. Числовые метрики схемы сюда **не переписываются**: их считает `npm run quality`,
   и любая зафиксированная в тексте цифра протухает после первой пересборки данных.
   Смотрите [`QUALITY.md`](QUALITY.md).
