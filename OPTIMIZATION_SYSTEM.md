# Система итеративного поиска оптимальных параметров

## Обзор

Изначально была задумана система автоматического поиска оптимальных параметров генерации схемы метро (поиск в глубину с отсечением худших вариантов).

**Текущее состояние репозитория:** документация ниже частично описывает исторический план. В текущем коде **нет** файла `scripts/optimize_params_depth_search.ts`, поэтому запуск “авто‑оптимизатора” по этой инструкции невозможен без восстановления скрипта.

При этом:

- `normalized/best_params.json` существует и может использоваться как справочник/артефакт подбора параметров.
- Основной пайплайн построения схемы сейчас идёт через `go-layout-solver` (см. `npm run build:data`) с опциональными якорями `normalized/yandex_coords.json` и ручными правками `normalized/layout_overrides.json`.

## Файлы

- **`normalized/best_params.json`** — набор “лучших” параметров, сохранённый как JSON (может не совпадать с текущей реализацией layout в Go).
- **`scripts/analyze_layout_advanced.ts`** — анализ метрик качества схемы.
- **`npm run build:data`** — пересборка `normalized/fullGraph.json` через `go-layout-solver`.

## Как работает

Оригинальная идея (если восстановить скрипт оптимизации) была такой:

1. **Начальная оценка** — оценить базовые параметры для получения начального скоринга.
2. **Поиск в глубину** — рекурсивно исследовать варианты параметров:
   - приоритетно оптимизировать важные параметры (радиусы колец, раздвижение);
   - генерировать варианты для каждого параметра;
   - отсеивать варианты, которые хуже лучшего на заданный порог (например, 15%);
   - продолжать только с лучшими вариантами (beam search).
3. **Оценка каждого варианта**:
   - пересобрать граф (`build:data` или эквивалентный вызов Go-решателя);
   - прогнать анализ метрик (`analyze_layout_advanced.ts`);
   - вычислить общий скоринг качества схемы.
4. **Сохранение лучшего** — сохранять лучшие параметры в `normalized/best_params.json`.

## Оптимизируемые параметры

### Радиусы колец

- `koltsevayaRadiusScale` - масштаб радиуса Кольцевой линии (6.0-11.0)
- `mccRadiusScale` - масштаб радиуса МЦК (4.0-7.0)
- `bklRadiusScale` - масштаб радиуса БКЛ (4.5-7.5)

### Раздвижение внутри кольца

- `innerMaxRatio` - максимальное расстояние от центра для раздвижения (0.45-0.60)
- `innerBorderRatio` - граница зоны раздвижения (0.95-1.0)
- `innerExplosionFactor` - фактор агрессивности раздвижения (7.0-13.0)

### Оптимизация позиций

- `minDistance` - минимальное желаемое расстояние между станциями (50-65px)
- `criticalDistance` - критически близкое расстояние (20-35px)
- `extremeDistance` - экстремально близкое расстояние (8-15px)

### Итерации алгоритмов

- `smoothingIterations1` - итерации первого сглаживания (6-12)
- `optimizationIterations` - итерации оптимизации позиций (20-35)
- `smoothingIterations2` - итерации финального сглаживания (8-15)

### Масштабирование

- `targetWidth` - целевая ширина карты (2000-2400px)
- `targetHeight` - целевая высота карты (1600-1800px)
- `padding` - отступы (120-180px)

## Использование

```bash
# Текущий рабочий цикл (без авто-оптимизатора):
npm run build:data
npm run analyze:layout
```

Если ты хочешь вернуть именно автоматический подбор параметров:
1. Нужно восстановить/добавить скрипт оптимизации (например, `scripts/optimize_params_depth_search.ts`).
2. Убедиться, что он умеет:
   - менять параметры Go-решателя (а не несуществующего “скрипта сборки”);
   - запускать `go run . ...` с фиксированными входами;
   - читать метрики из `normalized/layout_metrics.json`.

## Дальнейшие улучшения

Система может быть улучшена:

1. Увеличить количество итераций поиска
2. Добавить больше параметров для оптимизации
3. Использовать более сложные эвристики отсечения
4. Параллелизировать оценку вариантов
5. Добавить адаптивный выбор beam width

## Примечания

- `normalized/best_params.json` следует воспринимать как артефакт экспериментов и источник идей, а не как гарантированно используемую конфигурацию.
- Перед любыми “долгими” прогонками оптимизации полезно стабилизировать функцию качества в `analyze_layout_advanced.ts`, чтобы улучшения были измеримыми.
