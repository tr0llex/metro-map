## Цели (что считаем «успехом»)

### P0 (must)

- **Читаемость схемы на одном мобильном экране** без «каши» в центре.
- **Стабильная геометрия**: предсказуемые кольца/радиалы и поведение хабов.
- **Минимальная плотность**: заметно поднять минимальные расстояния и снизить число «слипаний».

### P1 (important)

- **Полировка подписей** (меньше коллизий и пересечений с линиями).
- **Визуальная консистентность с референсом** (Яндекс‑подобные паттерны).
- **Инфраструктура**: воспроизводимый пайплайн + контроль качества метриками.

### P2 (nice-to-have)

- Мультирегиональность, MCD, расширенная продуктовая полировка, аналитика.

## Итеративный план выполнения (I0–I5)

### I0 — Базовая измеримость (1–2 вечера)

- **Цель:** любая правка layout сразу сравнима и не ломает базовые инварианты.
- **Выходные артефакты:**
  - актуальный `normalized/layout_metrics.json` после каждого значимого изменения;
  - короткий “чеклист регресса” (что смотреть глазами: центр, кольца, 5–10 хабов).
- **Критерий завершения:** метрики считаются стабильно и их можно сравнивать между версиями.

### I1 — Плотность и раздвижение (P0)

- **Цель:** убрать самые заметные “слипания” и сделать центр читаемым.
- **Фокус:** Epic L0.
- **Критерий завершения:**
  - `veryClosePairsCount` заметно ниже текущего уровня;
  - `minStationDistance` растёт без деградации колец/хабов.

### I2 — Кольца (P0)

- **Цель:** стабилизировать форму БКЛ/МЦК, уменьшить эксцентриситет.
- **Фокус:** Epic L1.
- **Критерий завершения:** эксцентриситет БКЛ и МЦК снижен относительно текущих значений без сильной деградации плотности.

### I3 — Радиалы/коридоры/хабы (P0)

- **Цель:** убрать “ломаные” общие участки и добиться правильных входов/выходов в хабы.
- **Фокус:** Epic L2 + L3.
- **Критерий завершения:**
  - визуально общие участки выглядят как “коридоры”;
  - `transferEdgesWithoutCommonHub = 0`.

### I4 — Подписи и производительность (P1)

- **Цель:** улучшить читаемость подписей в центре и стабильность поведения при зуме.
- **Фокус:** Epic T0–T2 + R0–R2.
- **Критерий завершения:**
  - есть отчёт “худших подписей”;
  - подписи заметно реже пересекаются (визуально);
  - во время pan/zoom нет заметных лагов из-за перерасчёта.

### I5 — UX/Editor/Data/Infra (P1–P2)

- **Цель:** довести продукт до “приятно пользоваться” и сделать пайплайн устойчивым.
- **Фокус:** Epic U*, E*, D*, Infra.
- **Критерий завершения:** редактор и пайплайн позволяют быстро фиксить проблемные места и проверять регрессии.

## P0 — Layout / геометрия (читаемость карты)

### Epic L0 — Плотность и раздвижение

- **[P0] Развести экстремально близкие станции** (veryClose) с приоритетом центра.
- **[P0] Развести близкие пары** (close) без расползания окраин.
- **[P0] Ввести “локальный минимум расстояний”**: разные `minDistance` для центра/внешней зоны.
- **[P0] Анти-коллизии станций vs сегменты линий** (станция не должна “улетать” от линии).
- **[P0] Ограничить максимальные расстояния** (чтобы хвосты не становились слишком растянутыми).
- **[P0] Нормализовать масштаб в конце** так, чтобы метрики расстояний были сравнимы между версиями.

**Definition of Done (L0):**

- `veryClosePairsCount` и `closePairsCount` снижаются относительно текущего состояния.
- `minStationDistance` растёт относительно текущего состояния.
- Визуально: в центре нет явных “слипаний” станций (5–10 самых плотных зон проверяются руками).

### Epic L1 — Кольца

- **[P0] Снизить эксцентриситет БКЛ** без деградации радиалов.
- **[P0] Снизить эксцентриситет МЦК** (форма кольца + равномерность шага).
- **[P0] Зафиксировать “опорные углы” колец** (чтобы кольца не “проворачивались” от версии к версии).
- **[P0] Контроль равномерности шагов по кольцу** (не допускать кластеров точек).

**Definition of Done (L1):**

- Эксцентриситет БКЛ и МЦК снижен относительно текущих значений.
- Визуально: кольца не имеют “провалов” и локальных растяжений на 2–3 сегмента подряд.

### Epic L2 — Радиалы и “хорды”

- **[P0] Привязка радиалов к кольцам через хабы** (хорды вместо “лучей из центра”).
- **[P0] Правило “общего коридора”**: линии с общими станциями идут параллельно до точки развилки.
- **[P0] Разведение после общих участков** (с контролем порядка отрисовки и геометрии).
- **[P0] Запрет на “возврат назад”** (локальные подковы/петли) как явное ограничение.

**Definition of Done (L2):**

- Визуально: общие участки линий выглядят параллельно и расходятся “после развилки”, без хаотичного переплетения.
- Нет локальных “подков/петель” на основных ветках (ручная проверка на центре + нескольких радиалах).

### Epic L3 — Пересадки и хабы в layout

- **[P0] Свести `transferEdgesWithoutCommonHub` к 0** (данные/агрегация/хабы).
- **[P0] Жёсткая фиксация центра хаба** (станции хаба всегда в одной точке после всех оптимизаций).
- **[P0] “Вход/выход линий” в хаб**: сегменты должны реально сходиться в хабе, не проходить рядом.

**Definition of Done (L3):**

- `transferEdgesWithoutCommonHub = 0`.
- Визуально: у ключевых хабов линии сходятся в центр (не проходят “рядом”).
- При последующих оптимизациях плотности центр хаба не “расползается”.

## P1 — Подписи / читаемость / типографика

### Epic T0 — Диагностика проблем

- **[P1] Список “худших подписей”**: топ-N по score + причина (пересечение с текстом/станцией/линией).
- **[P1] Экспорт отчёта проблем подписей** (в JSON рядом с `layout_metrics.json`).

**Definition of Done (T0):**

- Есть воспроизводимый отчёт “top-N worst labels” с причинами.
- Отчёт используется как вход для итераций улучшения (T1/T2).

### Epic T1 — Алгоритм размещения

- **[P1] Bias по положению относительно центра** (подписи чаще наружу).
- **[P1] Bias по направлению линии** (если сегмент горизонтальный — предпочитать верх/низ).
- **[P1] Отдельные веса для пересечений с halo/линиями/маршрутом**.
- **[P1] Стабильность раскладки**: минимизировать “прыжки” подписи при малых изменениях.

**Definition of Done (T1):**

- Визуально на “центральном” скриншоте уменьшились пересечения подпись↔подпись и подпись↔станция.
- При небольшом pan/zoom подписи не “перекидываются” между противоположными сторонами без причины.

### Epic T2 — Длинные названия

- **[P1] Автоматический перенос на 2 строки** по словарю/правилам.
- **[P1] Мягкое уменьшение шрифта локально** для самых длинных названий.
- **[P1] Сокращения по словарю** (например, “просп.”, “пл.”) как опция.

**Definition of Done (T2):**

- Длинные названия читаемы и не перекрывают центр (перенос/уменьшение/сокращение).
- Не ухудшает читаемость на среднем и крупном зуме.

## P1 — Рендер / производительность

### Epic R0 — Режимы качества

- **[P1] Жёсткий “low quality mode” при активном pan** (упрощать слои, эффекты, хабы).
- **[P1] Жёсткий “low quality mode” при wheel-zoom**.
- **[P1] Гистерезис переключения режимов** (чтобы не мигало туда-сюда).

**Definition of Done (R0):**

- Во время pan/wheel-zoom FPS не проседает из-за тяжёлой отрисовки.
- Переходы между режимами не создают “мигания” слоёв.

### Epic R1 — Подписи (performance)

- **[P1] Пересчёт подписей только для видимой области + margin**.
- **[P1] Throttle/debounce по времени** для пересчёта подписей.
- **[P1] Кэширование `measureText`** (по строке и fontPx).

**Definition of Done (R1):**

- Пересчёт подписей не блокирует взаимодействие.
- Нет лишних полных пересчётов при небольших изменениях.

### Epic R2 — Отрисовка карты

- **[P1] Кэш базового слоя карты** (bitmap) при статике.
- **[P1] Перерисовка маршрута поверх кэша** без полной перерисовки базы.
- **[P1] Профилирование hot spots** (какие куски отрисовки “жрут” кадр).

**Definition of Done (R2):**

- При статичном вьюпорте карта не перерисовывается полностью без причины.
- Переключение маршрутов/вариантов не требует перерисовки базы.

## P1 — UX

### Epic U0 — Выбор станций

- **[P1] Поповер по тапу**: “Откуда / Куда / Закрыть”.
- **[P1] “Активное поле ввода”** (тап по станции заполняет именно его).
- **[P1] Быстрое действие “Поменять местами”** на шторке/в саммари.

**Definition of Done (U0):**

- Выбор “Откуда/Куда” по тапу занимает 1–2 действия.
- На мобайле сценарий понятен без лишних модалок.

### Epic U1 — Маршруты

- **[P1] Ярлыки альтернатив** (“Самый быстрый”, “Меньше пересадок”) всегда консистентны.
- **[P1] Настройка штрафа пересадок** (ползунок/пресеты) для альтернатив.
- **[P1] Пояснение длинных переходов** (бейджи/подсказки) и подсветка на карте.

**Definition of Done (U1):**

- Альтернативы имеют понятные ярлыки и объяснимый смысл.
- “Длинные переходы” заметны и объяснены.

### Epic U2 — Карточка станции

- **[P1] Базовая карточка станции** (линии, пересадки, действия).
- **[P1] Интеграция “маршрут отсюда/сюда”** из карточки.

**Definition of Done (U2):**

- Карточка открывается из карты и из шагов маршрута.
- Из карточки можно начать построение маршрута.

## P1 — Editor / workflow

### Epic E0 — Экспорт/импорт

- **[P1] Экспорт `editor_overrides.json` как файл** (download).
- **[P1] Импорт `editor_overrides.json`** обратно в редактор.
- **[P1] Пресеты оверрайдов** (несколько наборов).

**Definition of Done (E0):**

- Оверрайды можно сохранить как файл и восстановить без ручного копирования.
- Экспортируемый JSON совместим с Go-пайплайном.

### Epic E1 — Инварианты и проверки

- **[P1] Проверка консистентности после правок** (хабы/пересадки/дубликаты/изолированные станции).
- **[P1] Авто-подсветка проблемных узлов** на карте в режиме редактора.

**Definition of Done (E1):**

- После правок редактор явно показывает нарушения инвариантов.
- Есть быстрый путь “найти и исправить” топ проблем.

## P2 — Данные / реализм / расширения

### Epic D0 — Времена и веса

- **[P2] Модель времени перегонов** (приближение по гео-длине как минимум).
- **[P2] Модель времени пересадок** (по типу: внутри хаба / out-of-station).

**Definition of Done (D0):**

- Время маршрута объяснимо и стабильно при перегенерации графа.
- Разные типы пересадок имеют разные веса/времена.

### Epic D1 — ETL

- **[P2] GTFS/OSM импорт (черновой)**.
- **[P2] Сопоставление ID станций** между источниками.

**Definition of Done (D1):**

- ETL воспроизводим и выдаёт валидный `fullGraph.json`.
- Консистентность ID гарантируется (валидация).

### Epic D2 — Multi-city / MCD

- **[P2] Multi-city support** (несколько графов + выбор города).
- **[P2] MCD integration** (D1–D4 как отдельные линии со своим стилем).

**Definition of Done (D2):**

- Можно переключать город без изменения кода.
- МЦД интегрируется в маршрутизацию и визуально отличим.

## P2 — Инфраструктура и качество

- **[P2] Минимальный набор тестов** для маршрутизатора и импорта данных.
- **[P2] “Золотые метрики”**: автосравнение `layout_metrics.json` между версиями.
- **[P2] Скриншот‑регрессии** (центр/ключевые хабы) для визуального контроля.

**Definition of Done (Infra):**

- Есть минимум автопроверок, чтобы не деградировать метрики и визуал.
- Сравнение метрик и базовые визуальные проверки встроены в процесс.
